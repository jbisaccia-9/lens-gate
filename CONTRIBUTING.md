# Contributing

Thanks for considering a contribution. This repo is part of a small family of "-gate" projects that each enforce one measured bar before letting something ship — please keep contributions in that spirit.

## Ground rules

- **The gate must still pass.** Every PR needs to pass the existing gate suite (CI on this repo), in both directions: the seeded morning must clear, the planted drift must be reported, and all six counterexamples must be refused, each for its own rule.
- **New rule, new counterexample.** If you add a rule to `gate.py`, add a turn to `counterexamples.py` that only that rule catches, a test that makes it fire and a test that lets it pass. If you add a check inside an existing rule, add a test that isolates it — a counterexample that fails for two reasons only proves one of them.
- **Access lives in `policy.yaml`.** Don't hard-code a role, connection or collection anywhere else. The warehouse grants are generated from it (`python -m lensgate ddl --roles`); regenerate `docker/initdb/02-roles.sh` if you change it.
- **Data stays synthetic.** Every person, store, group id and number here is fictional and generated by `seed.py`. Don't add real names, real exports, credentials, keys, tokens or anything proprietary. Configuration is by environment variable *name* only.

## Getting started

1. Fork the repo and clone your fork.
2. Follow the offline Quickstart in the README — no credentials or Docker needed.
3. Run `pytest`, the demo, `check-dir` on the counterexamples, `python scripts/make_results.py` and `python scripts/build_site.py` before opening a PR (a test fails if `docs/index.html` is stale).
4. Open a PR against `main`. Small, focused PRs are easier to review than large ones.
